# Offline WinForms UI review harness

Build with `dotnet build tests/UiReviewTests/UiReviewTests.csproj -c Release --ignore-failed-sources`. Run the resulting executable with `inventory`, `audit`, `regressions`, `behavior`, `roundtrip`, `sort-reference`, `clock-combo`, or `all-combos`, followed by an absolute artifact folder. `--filter NAME[,NAME]` limits object types; `--timeout 30` bounds each general model worker. Use a fresh output folder for each source snapshot.

The project references the production UI project. Inventory discovers every compiled non-abstract Form, including internal types. IGXDLMSView plus GXDLMSViewAttribute identifies object views. Additional dialog constructors are inventoried; the companion UiDialogReviewTests suite handles their safe fixtures.

Each view receives blank and representative in-memory models within a parent collection. Table fixtures cover Association object lists, Profile Generic buffers/capture objects, active/passive Activity Calendar tables, Register Monitor thresholds/actions, Action Schedule, Push targets, Script actions, and certificate metadata. Structured Data is an additional case. Other protocol-specific collection branches remain at defaults and are recorded as limitations.

Rendering uses production ModernPresentation.Apply, GXDlmsUi.Init, and GXDlmsUi.ObjectChanged. Connected semantics enable controls locally; no transport exists, no command is submitted, and validation is disabled. The runner uses nonactivating offscreen windows. Monitor regressions use invisible nonactivating hosts on the real available screens, settling host DPI before constructing/binding child views. Each model runs in its own timeout-bounded worker; partial/error results survive failure.

Every tab is selected with its ancestor tabs at 1100x760 and 620x560. Each scrollable surface is captured at top and bottom. Results include screenshots, control bounds, overlap/label/accessibility candidates, scrolling, assembly hashes, compiled inventory, regression checks, CSV summaries, coverage ledger, and narrow contact sheets. DrawToBitmap has native clipping/rendering limitations; candidates need visual/source confirmation and do not imply automatic defects. No claim is made for screen readers, all DPIs, high contrast, all possible tab combinations, or exhaustive protocol variants.

Regressions cover readable shared fields, simple-editor horizontal scrolling, structured Data multirow display and same-view scalar/Array/Structure transitions, dirty-then-clean error indicators across supported attributes, Clock timezone/DST access, Push destination access, live Association conformance state, Saudi flags roundtrip, and wide-narrow-wide layout restoration on real 96/120 DPI monitors when available. Behavioral toggles change only disposable in-memory fixtures. A nonzero exit code means a model case or regression failed; inspect results.json/regressions.json.

`sort-reference` is the focused Profile Generic regression matrix added on 2026-10-30. It seeds attribute 6 explicitly as `Structure` with read access and supplies empty, Clock, Register, and long-description states. Populated references use real capture objects, attribute 2, and data index 0. Each of four isolated workers moves the same native host through every available physical monitor and back to its origin. At each monitor it captures 1100x760, 620x560, wide restoration, minimize/restore, maximize/restore, and same-view null → populated → null refreshes through `GXDlmsUi.ObjectChanged`. This mode defaults to a 90-second worker timeout, overridable with `--timeout`.

The focused checks require `SortObjectReference` and the native read-only `ReferenceIdentity`/`ReferenceDetails` textboxes, with the obsolete `SortObjectTB` absent. They verify reference identity and indices, empty-state details visibility, wrapping without inner scrollbars, native text-line height, selection/copy affordances, inherited font size, containment, no parent horizontal scrolling, and width/DPI/minimize restoration. Selection is tested without reading or writing the clipboard. `sort-reference-summary.json` records exact observed DPI, case, capture, and assertion counts alongside the ordinary results and assembly hash. This matrix closes the earlier scalar-only fixture gap; it does not claim all protocol metadata or screen-reader coverage.

`clock-combo` is the focused native Clock base matrix added on 2026-10-30. Four isolated workers cover connected editable, connected unread, connected read-only and disconnected states. ClockBaseTB is explicitly bound to enum attribute 9. The six native typed ClockBase options must retain their order and numeric mapping; selecting each option through the native control must update the disposable model and dirty indicator, then survive a clean production binding refresh. Unread values must stay blank until a read timestamp arrives. Read-only/disconnected combos remain disabled, while writable combos retain their native keyboard focus target.

Each Clock worker moves the same view across every actual monitor and back, checking wide/narrow/wide, minimize/restore and maximize/restore. Captures include scroll top/bottom for review of the full Clock editor. Checks require the original GXValueField and ComboBox instances, attribute/type binding, zero wrapper padding, wrapper background matching its parent, no rendered secondary wrapper border, native PreferredHeight, full field width, vertical centering, containment and inherited fonts. Existing Clock timezone/DST access and dirty/clean regressions also run. `clock-combo-summary.json` records exact coverage and assembly identity; the worker timeout defaults to 90 seconds. No meter action, transport, user setting or global keyboard input is used.

Clock native height verification explicitly assigns PreferredHeight and checks the resulting native height. A stable native coercion of at most two pixels is accepted only when the text viewport still fits the font; full width, centering and containment remain checked. Monitor restoration permits the existing two-pixel DPI rounding tolerance, then a second physical roundtrip requires stable field/combo sizes and restored font size to catch accumulating shrinkage.

`all-combos` targets the 38 object views with 96 visible combos recorded across the prior 73-view/147-fixture matrix, plus Data's metadata-driven enum editor. It uses representative populated models, adds Security Setup version 0, and runs each selected fixture on every physical monitor at wide/narrow/restored-wide sizes with all tabs and scroll top/bottom captures. The historical inventory is provenance for selecting affected screens, not a fresh negative assertion about the remaining views. `combo-inventory.json`/`.csv` distinguish native combos actually observed visible from inactive generic GXValueField children; `combo-summary.json` records current assembly, coverage and failures.

All visible native combos are checked for readable height (including explicitly verified native coercion), containment, keyboard availability and absence of ModernFieldFrame. GXValueField/native combo hosts must have zero padding, parent background, no secondary border pixels, full width and centered native height. Each safe typed enum field additionally tests a real native selection commit, clean refresh, unread blank state, read-only and disconnected access. Explicit direct Register/Extended/Demand Unit and Push fixtures verify selection mapping. Other direct protocol mappings are recorded as layout/items coverage rather than generically mutated. Data runs TextBox → ComboBox → TextBox transitions with explicit numeric enum metadata, mapping/readonly/unread checks, and restored scalar padding/background/border. Prior focused Clock and Sort suites remain available.

Representative non-flags enum properties with undefined constructor defaults are seeded with their first defined value. The combo suite uses supported G3 PLC 6LoWPAN and M-Bus Client model versions so device type (attribute 19) and encryption-key status (attribute 14) are actually bindable. Their version 0 views currently leave these later attributes visible but unbound; that older-version observation is retained as a limitation rather than used as populated enum coverage.


Combo captures preserve the requested scroll position around binding/native-size probes. A native combo must fit the horizontal editor viewport or have a usable ancestor horizontal scrollbar. The capture pass also reveals individual children when nested scroll surfaces leave them clipped in both top and bottom captures; contact-sheet selection checks every ancestor viewport, not only the form rectangle.

Register Activation supplies one assignment and Day/Night masks. The ActiveMasksCb checks require a standard native frame inside NativeComboHost, exercise a real selection commit, then refresh the whole object so clear/repopulate transient deselection cannot alter ActiveMask, leave it dirty, or open a modal error.

The complete scalar-width and structured-area audit is documented in ../UiLayoutAudit.README.md. Its separate layout-only worker mode preserves the behavioral suites above.

## Focused Activity Calendar audit

Run `UiReviewTests.exe calendar <output> --timeout 90` against a frozen UI snapshot. It launches isolated workers for empty, populated and long-name models on every currently connected physical monitor. Each worker renders all six active/passive Season/Week/Day pages at 1100×760, 620×560 and restored 1100×760; extra scroll captures are retained when needed.

The fixtures use distinct active/passive objects, two seasons, two weeks and two days with two scheduled actions each. Assertions cover original binding instances, exact refreshed names, same-view empty/populated/empty refreshes, selected-day action binding, field rails/fonts/colors, padded field height and native text viewport, and actual table row allocation. This catches skinny field wrappers even when their raw height equals the font height. The test also invokes nonmodal Remove buttons on disposable models, checks the correct collection and opposite-side isolation, and verifies access/dirty states. It does not invoke meter activation, Add/Edit modal dialogs, network transport or user preferences.

Read `calendar-summary.json`, `regressions.json`, per-case `result.json` and the actual screenshots together. Unconnected 96 DPI displays are not simulated. Long ASCII values remain intact and use native text/list navigation; the matrix does not claim every protocol encoding, locale, keyboard path or meter response is covered.

## Complete button audit

The button audit reuses the existing isolated worker: `UiReviewTests.exe worker <object-type> <state> <output> <monitor-index> buttons`. Each case renders normal 1100x760, medium 900x650, narrow 620x560 and restored normal sizes, every tab and scroll-reachable action. The compiled inventory reports Button/GXButton fields separately from buttonless views. Source semantic groups identify list footers, field methods, inline actions and header stacks; these roles do not share an arbitrary universal position. Current scope is 44 button-bearing object views/195 original fields and 29 buttonless views, with explicit Italy, version and disconnected branches.

`ButtonAuditMetrics.cs` records parent-relative outer bounds and actual HWND geometry, full ancestor clipping, native text/preferred size/padding, original instances and action indices, enabled state, fonts and colors. Use the parent's transform of Location for outer bounds; adding outer size to the control's client-origin transform creates false border offsets. The dedicated `roundtrip` state uses the same worker for a bounded actual 96/120 DPI move/minimize/maximize gate; Calendar forces 320 physical pixels so its footer genuinely wraps at both scales. No global pointer/keys, meter action or persistent setting is used.

Shared action rules are 32 logical pixels for object/custom actions and 28 for native modal confirmations, 8 between peers, 4 between a direct list and its footer, 4 at footer ends, and measured text room with a reserve. Header/inline/icon/browse/native-arrow/toolstrip roles remain explicit exceptions. AutoSize-column confirmation groups stay on one row. Fixed footer buttons must fit through every ancestor at each capture; an AutoScroll flag alone never excuses a hidden Cancel button. Scrollable body actions are judged across that exact viewport/tab/DPI scenario's reveal captures.

Accepted evidence retains each actual source assembly hash. Later scoped fixes replace only matching affected cases; raw earlier failures, insufficient stress states and superseded geometry remain intact. Review native screenshots as well as metrics: preferred-size text measurements alone previously missed a final clipped letter. `MemoryProfileSettings` rejects settings saves before construction. Known test-host foreground activation and native bitmap limitations remain; this is layout/binding evidence, not a claim that every meter operation or all possible protocol inputs were executed.
